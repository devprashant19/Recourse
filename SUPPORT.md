# Support & Community Resources

Welcome to Recourse! We are committed to providing responsive, transparent support for developers, operators, and open-source contributors.

---

## Getting Help

### 1. General Questions & Discussions
For questions about how Recourse works, protocol concepts, architectural decisions, or integration ideas:
- **[GitHub Discussions](https://github.com/devprashant19/Recourse/discussions):** Ask questions, share ideas, and connect with other contributors.
- If Discussions are not enabled on your view, feel free to open a [GitHub Issue](https://github.com/devprashant19/Recourse/issues/new) labeled `question`.

### 2. Bug Reports
If you encounter unexpected behavior, test failures, or bugs:
- Check existing [GitHub Issues](https://github.com/devprashant19/Recourse/issues) to see if the issue has already been reported.
- If not, open a new issue using the **[Bug Report Template](https://github.com/devprashant19/Recourse/issues/new?template=bug_report.yml)**.
- Please provide your environment details (OS, Node version, pnpm version, Rust version) and reproduction steps.

### 3. Feature Requests & Improvements
If you have suggestions for protocol improvements, new SDK features, or developer experience enhancements:
- Open a new issue using the **[Feature Request Template](https://github.com/devprashant19/Recourse/issues/new?template=feature_request.yml)**.
- Clearly describe the problem you want to solve and your proposed solution.

### 4. Security Vulnerabilities
If you discover a security vulnerability in smart contracts, cryptographic verification logic, or services:
- **Do NOT open a public issue.**
- Submit a private report through [GitHub Security Advisories](https://github.com/devprashant19/Recourse/security/advisories/new).
- See [SECURITY.md](SECURITY.md) for complete disclosure guidelines.

---

## Communication Channels Note

All official project communication, technical design discussions, issue triage, and governance happen transparently in this GitHub repository.

Recourse does not operate separate Discord, Telegram, or Slack servers for official governance or support. Any third-party channels claiming to represent official Recourse support should be treated with caution.
